# code-drill 24주 커리큘럼

6개월(24주) 동안 **개념 → 패턴 → 문제**를 한 사이클로 도는 학습 코스입니다.
문제만 푸는 사이트가 아니라, 매주 "왜 이 도구를 쓰는가"를 먼저 이해하고 그 도구로 풀리는
문제를 4개씩 풀어 체화하는 구조입니다.

## 설계 원칙

1. **난이도는 단조 증가.** 1~6주는 쉬움 위주, 마지막 페이즈에서 어려움이 나옵니다.
   각 주 안에서도 `워밍업 → 핵심 2문제 → 도전 1문제` 순으로 올라갑니다.
2. **개념이 먼저.** 각 주는 읽는 데 10분 정도 걸리는 개념 노트로 시작합니다.
   원리 + 코드 템플릿 + **자주 틀리는 함정**을 함께 담습니다.
3. **앞 주차만으로 풀린다.** N주차 문제는 1~N주차에서 배운 도구만으로 풀 수 있습니다.
   (예외: 1주차 `두 수의 합`은 O(n²) → O(n) 개선을 체감시키려고 해시를 미리 맛봅니다.)
4. **6주마다 체크포인트.** 6·12·18·24주는 새 개념 대신 복습과 미니 모의고사입니다.
   유형을 알려주지 않고 섞어 내서, "무슨 도구를 꺼낼지 고르는 능력"을 따로 훈련합니다.
5. **주 4문제, 총 96문제.** 하루 1문제 페이스가 아니라 주 4문제 페이스입니다.
   밀렸을 때 따라잡을 여유를 남기려는 의도입니다.

## 주간 루틴

| 단계 | 내용 | 예상 시간 |
| --- | --- | --- |
| 1. 개념 노트 | 원리, 언제 쓰는지, 복잡도, 함정 | 10분 |
| 2. 패턴 코드 | JS/Python 템플릿 (외우지 말고 손으로 한 번 치기) | 10분 |
| 3. 문제 4개 | 워밍업 1 · 핵심 2 · 도전 1 | 2~4시간 |
| 4. 셀프 체크 | 개념 질문 3개에 말로 답하기 | 5분 |

## 페이즈 1 · 기초 체력 (1~6주)

배열·해시·문자열·정렬처럼 **모든 문제의 바닥에 깔리는 도구**를 손에 붙입니다.
이 페이즈의 목표는 "알고리즘을 아는 것"이 아니라 **언어를 도구로 쓰는 데 막힘이 없는 상태**입니다.

### 1주차 — 시간 복잡도와 배열

> 개념: Big-O 읽는 법 / 입력 크기로 알고리즘 고르기 / 배열 순회와 인덱스 / 시간 초과의 정체

핵심은 이 표를 외우는 것입니다. 문제의 제한 조건을 보고 **역산해서** 알고리즘을 고릅니다.

| n 제한 | 허용 복잡도 | 대표 도구 |
| --- | --- | --- |
| n ≤ 20 | O(2ⁿ), O(n!) | 완전 탐색, 백트래킹 |
| n ≤ 5,000 | O(n²) | 이중 반복문, 2차원 DP |
| n ≤ 200,000 | O(n log n) | 정렬, 이분 탐색, 힙 |
| n ≤ 10,000,000 | O(n) | 한 번 순회, 투 포인터 |

| # | 문제 | 난이도 | 배우는 것 |
| --- | --- | --- | --- |
| 1 | 배열의 합과 최댓값 | 쉬움 | 순회 기본, 언어별 배열 API |
| 2 | 두 번째로 큰 수 | 쉬움 | 정렬하지 않고 한 번 순회로 |
| 3 | **두 수의 합** ✅ | 쉬움 | O(n²) 브루트포스 → O(n) 해시 |
| 4 | 구간 합 구하기 | 쉬움 | 누적합의 첫 등장 |

셀프 체크: `O(n²)`와 `O(n log n)`은 n=100,000에서 몇 배 차이인가? / 배열 중간 삽입이 O(n)인 이유는?

### 2주차 — 해시: 맵과 셋

> 개념: 해시 테이블 원리(버킷·충돌) / 평균 O(1)의 의미 / JS `Map`·`Set` vs 객체 / Python `dict`·`set`·`Counter` / 빈도수 패턴

"이미 본 적 있나?"와 "몇 번 나왔나?"를 O(1)에 답하는 것이 이 주의 전부입니다.

| # | 문제 | 난이도 | 배우는 것 |
| --- | --- | --- | --- |
| 1 | 중복 원소 찾기 | 쉬움 | Set으로 본 적 판정 |
| 2 | 가장 많이 등장한 문자 | 쉬움 | 빈도수 맵 |
| 3 | 두 배열의 교집합 | 쉬움 | 집합 연산 |
| 4 | 가장 긴 연속 수열 | 보통 | 정렬 없이 O(n)으로 — 셋의 응용 |

셀프 체크: 해시가 최악에 O(n)이 되는 경우는? / JS에서 객체 대신 `Map`을 써야 할 때는?

### 3주차 — 문자열

> 개념: 문자열 불변성 / 슬라이싱 / `split`·`join` / 문자↔코드(`charCodeAt`·`ord`) / **반복 연결이 O(n²)인 함정**

| # | 문제 | 난이도 | 배우는 것 |
| --- | --- | --- | --- |
| 1 | 문자열 뒤집기 | 쉬움 | 인덱싱과 슬라이싱 |
| 2 | 팰린드롬 검사 | 쉬움 | 정규화 후 양끝 비교 |
| 3 | 애너그램 판별 | 쉬움 | 정렬 vs 빈도수, 두 풀이 비교 |
| 4 | 문자열 압축 (RLE) | 보통 | 연속 구간 스캔, 버퍼로 이어붙이기 |

셀프 체크: 루프에서 `s += c`를 10만 번 하면 왜 느린가?

### 4주차 — 정렬

> 개념: 내장 정렬의 복잡도 / **JS `sort()`가 기본으로 문자열 비교라는 함정** / 커스텀 비교자 / Python `key=` / 안정 정렬 / 다중 기준 / 버블·삽입·병합 정렬의 원리

이 주의 진짜 교훈은 "정렬 알고리즘을 짜는 법"이 아니라 **정렬하면 쉬워지는 문제를 알아보는 눈**입니다.

| # | 문제 | 난이도 | 배우는 것 |
| --- | --- | --- | --- |
| 1 | 다중 기준 정렬 | 쉬움 | 비교자 작성, 안정 정렬 |
| 2 | K번째 큰 수 | 쉬움 | 정렬 후 인덱스 |
| 3 | 회의 시간 겹침 판정 | 보통 | 시작 시각 정렬 후 스캔 |
| 4 | **애너그램 묶기** ✅ | 보통 | 정렬을 해시 키로 쓰기 |

셀프 체크: `[10, 9, 1].sort()`가 JS에서 왜 `[1, 10, 9]`인가?

### 5주차 — 투 포인터와 슬라이딩 윈도우

> 개념: 정렬된 배열의 양끝 포인터 / 고정 길이·가변 길이 윈도우 / **포인터가 되돌아가지 않아 O(n)인 이유**

| # | 문제 | 난이도 | 배우는 것 |
| --- | --- | --- | --- |
| 1 | 정렬된 배열의 두 수의 합 | 쉬움 | 양끝 포인터 |
| 2 | 정렬된 배열 중복 제거 | 쉬움 | 읽기/쓰기 포인터 분리 |
| 3 | **가장 큰 연속 부분 수열의 합** ✅ | 보통 | 카데인 알고리즘 |
| 4 | **중복 없는 가장 긴 부분 문자열** ✅ | 보통 | 가변 윈도우 + 해시 |

셀프 체크: 투 포인터가 정렬을 전제하는 문제와 아닌 문제의 차이는?

### 6주차 — 체크포인트 1 🏁

> 복습: 1~5주 지도 / **문제 유형 → 도구 매핑 체크리스트** / 코테 시간 배분 기초

유형을 알려주지 않은 혼합 4문제. 실제 시험처럼 90분 타이머를 걸고 풉니다.

| # | 문제 | 난이도 |
| --- | --- | --- |
| 1 | 완주하지 못한 선수 | 쉬움 |
| 2 | 로그 파일 재정렬 | 쉬움 |
| 3 | 합이 target인 최단 구간 | 보통 |
| 4 | 가장 긴 팰린드롬 부분 문자열 | 보통 |

## 페이즈 2 · 탐색과 재귀 (7~12주)

"모든 경우를 어떻게 빠짐없이, 그러나 낭비 없이 훑는가"를 배웁니다.
난이도가 쉬움에서 보통으로 넘어가는 구간입니다.

### 7주차 — 스택 · 큐 · 덱

> 개념: LIFO/FIFO / **배열을 큐로 쓰면 `shift()`가 O(n)인 함정** (`deque`, 인덱스 포인터) / 단조 스택

| # | 문제 | 난이도 | 배우는 것 |
| --- | --- | --- | --- |
| 1 | **올바른 괄호** ✅ | 쉬움 | 스택의 교과서 |
| 2 | 최근 K개의 이동 평균 | 쉬움 | 큐/덱 |
| 3 | 후위 표기식 계산 | 보통 | 스택으로 수식 처리 |
| 4 | 다음 큰 원소 | 보통 | 단조 스택 — O(n²)를 O(n)으로 |

### 8주차 — 이분 탐색

> 개념: 정렬 전제 / **무한 루프를 만드는 경계 처리** / `lower_bound`·`upper_bound` / **정답을 이분 탐색하기(파라메트릭 서치)**

| # | 문제 | 난이도 | 배우는 것 |
| --- | --- | --- | --- |

| 2 | 삽입 위치 찾기 | 쉬움 | lower bound 변형 |
| 3 | 회전된 정렬 배열에서 검색 | 보통 | 조건이 깨진 이분 탐색 |
| 4 | 랜선 자르기 | 보통 | **답을 이분 탐색** — 사고 전환 |

셀프 체크: `mid = (lo + hi) / 2`와 `lo + (hi - lo) / 2`의 차이는? / 파라메트릭 서치가 가능한 조건은?

> 개념: 기저 조건 / 콜 스택과 스택 오버플로 / **Python 재귀 깊이 제한** / 재귀 ↔ 반복 변환 / 분할 정복

| --- | --- | --- | --- |

## 페이즈 3 · 알고리즘 패러다임 (13~18주)

### 15주차 — 그리디

> 개념: **그리디가 통하는 조건**(탐욕 선택 속성 + 최적 부분 구조) / 반례를 먼저 찾는 습관 / 정렬 후 선택 패턴 / 교환 논증

이 주는 마지막 문제로 **그리디가 실패하는 순간**을 직접 겪게 하고, 그대로 16주차 DP로 넘깁니다.

| # | 문제 | 난이도 | 배우는 것 |

| 4 | **거스름돈 (임의 화폐)** ✅ | 보통 | **그리디 실패 → DP 필요** |

| # | 문제 | 난이도 | 배우는 것 |
| --- | --- | --- | --- |
