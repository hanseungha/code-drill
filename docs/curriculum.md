# code-drill 24주 커리큘럼

6개월(24주) 동안 **개념 → 패턴 → 문제**를 한 사이클로 도는 학습 코스입니다.
문제만 푸는 사이트가 아니라, 매주 "왜 이 도구를 쓰는가"를 먼저 이해하고 그 도구로 풀리는
문제를 4개씩 풀어 체화하는 구조입니다.

## 설계 원칙

1. **난이도는 단조 증가.** 1~6주는 쉬움 위주, 마지막 페이즈에서 어려움이 나옵니다.
   각 주 안에서도 `워밍업 → 핵심 2문제 → 도전 1문제` 순으로 올라갑니다.
2. **개념이 먼저.** 각 주는 읽는 데 10분 정도 걸리는 개념 노트로 시작합니다.
   원리 + 코드 템플릿 + **자주 틀리는 함정**을 함께 담습니다.
3. **앞 주차만으로 풀린다.** N주차 문제는 1~N주차에서 배운 도구만으로 풀 수 있습니다.
4. **체크포인트는 세 번.** 6·12·24주는 새 개념 대신 복습과 미니 모의고사입니다.
   유형을 알려주지 않고 섞어 내서, "무슨 도구를 꺼낼지 고르는 능력"을 따로 훈련합니다.
   체크포인트를 네 번에서 세 번으로 줄인 것은 필수 주제 21개를 24주 안에 넣기 위해서입니다.
5. **주 4문제, 총 96문제.** 하루 1문제 페이스가 아니라 주 4문제 페이스입니다.
   밀렸을 때 따라잡을 여유를 남기려는 의도입니다.

## 페이즈 1 · 기본기 (1~6주)

문법과 복잡도를 점검하고, 배열·문자열·완전탐색·해시로 문제를 일단 풀어냅니다.

### 1주차 — 시작하기: 문법과 복잡도

두 언어의 문법 차이를 정리하고, 제한 조건에서 알고리즘을 역산하는 법을 익혀요.

**개념** — 이 사이트의 입출력 규약 · 연산자에서 갈리는 곳 · 시간 복잡도 · 공간 복잡도

**패턴 코드** — 반복문 관용구 · 함수와 여러 값 반환 · 조건 분기를 짧게 쓰기

| 역할 | 문제 | 배우는 것 |
| --- | --- | --- |
| 워밍업 | **몫과 나머지** ✅ | 두 언어의 정수 나눗셈 차이를 직접 겪기 |
| 워밍업 | **FizzBuzz** ✅ | 조건 분기의 순서 — 15의 배수를 먼저 봐야 하는 이유 |
| 핵심 | **최솟값과 최댓값** ✅ | 한 번 순회로 두 값을 구하고 함께 반환하기 |
| 도전 | **약수 구하기** ✅ | O(n)을 O(√n)으로 줄이며 복잡도를 체감하기 |

### 2주차 — 배열: 1차원과 2차원

순회·누적합·차분, 그리고 격자를 다루는 기본기.

**개념** — 2차원 배열 · 누적합 · 차분 배열

**패턴 코드** — 2차원 배열 만들고 훑기 · 누적합으로 구간 합을 O(1)에 답하기 · 차분 배열로 구간 갱신

| 역할 | 문제 | 배우는 것 |
| --- | --- | --- |
| 워밍업 | **배열의 합과 최댓값** ✅ | 순회 기본과 언어별 배열 API |
| 핵심 | **행의 합이 가장 큰 줄** ✅ | 2차원 배열을 행 단위로 훑기 |
| 핵심 | **구간 합 구하기** ✅ | 누적합으로 질문마다 O(1)에 답하기 |
| 도전 | **구간에 값 더하기** ✅ | 차분 배열 — 갱신을 O(1)로 미루기 |

### 3주차 — 문자열

불변 문자열을 다루는 법과, 이어붙이기가 만드는 함정을 배워요.

**개념** — 기본 도구 · 양끝에서 좁혀오기

**패턴 코드** — 조각을 모았다가 한 번에 합치기 · 알파벳을 인덱스로 쓰는 빈도수 배열 · 양끝에서 좁혀오며 대칭 확인

| 역할 | 문제 | 배우는 것 |
| --- | --- | --- |
| 워밍업 | **문자열 뒤집기** ✅ | 인덱싱과 슬라이싱에 익숙해지기 |
| 핵심 | **팰린드롬 검사** ✅ | 정규화 후 양끝 비교 |
| 핵심 | **애너그램 판별** ✅ | 정렬 풀이와 빈도수 풀이를 둘 다 써보고 비교하기 |
| 도전 | **문자열 압축** ✅ | 연속 구간 스캔과 버퍼로 이어붙이기 |

### 4주차 — 완전탐색과 시뮬레이션

가능한 경우를 빠짐없이 만들어 보기. 모든 최적화의 출발점이에요.

**개념** — 경우를 만드는 세 가지 틀 · 비트마스크로 부분집합 열거하기 · 시뮬레이션 · 경계 조건 체크리스트

**패턴 코드** — 모든 쌍과 모든 구간 훑기 · 비트마스크로 부분집합 전체 순회 · 델타 배열과 방향 회전 · 턴마다 새 배열에 쓰기

| 역할 | 문제 | 배우는 것 |
| --- | --- | --- |
| 워밍업 | **세 수의 합** ✅ | 삼중 반복문으로 모든 경우를 만들어 보기 |
| 핵심 | **부분집합의 합** ✅ | 비트마스크로 2ⁿ개 부분집합 순회하기 |
| 핵심 | **행렬 90도 회전** ✅ | 전치 후 뒤집기로 나눠 생각하기 |
| 도전 | **로봇 시뮬레이션** ✅ | 방향과 위치를 상태로 관리하기 |

### 5주차 — 해시: 맵과 셋

'본 적 있나?'와 '몇 번 나왔나?'를 O(1)에 답하는 도구예요.

**개념** — 맵과 셋, 무엇을 쓸까 · 빈도수 세기가 절반이에요

**패턴 코드** — 빈도수 세기 · 본 적 있는지 판정하며 진행하기

| 역할 | 문제 | 배우는 것 |
| --- | --- | --- |
| 워밍업 | **중복 원소 찾기** ✅ | 셋으로 '본 적 있나' 판정하기 |
| 핵심 | **가장 많이 등장한 문자** ✅ | 빈도수 맵을 만들고 최댓값 뽑기 |
| 핵심 | **두 수의 합** ✅ | O(n²) 브루트포스를 O(n) 해시로 줄이는 경험 |
| 도전 | **가장 긴 연속 수열** ✅ | 정렬하지 않고 셋만으로 O(n)에 푸는 발상 |

### 6주차 — 체크포인트 1 🏁

1~5주 복습. 유형을 감추고 섞어 내서 도구를 고르는 힘을 길러요.

**개념** — 도구 선택 체크리스트 · 시간 배분 연습

| # | 모의고사 문제 |
| --- | --- |

## 페이즈 2 · 탐색의 기술 (7~12주)

완전탐색의 낭비를 줄이는 다섯 가지 방법 — 정렬, 투 포인터, 그리디, 스택·큐, 이분 탐색.

### 7주차 — 정렬

정렬 알고리즘을 짜는 법이 아니라, 정렬하면 쉬워지는 문제를 알아보는 눈.

**개념** — 비교자와 키 · 안정 정렬 · 원리는 알아두기 · 좌표 압축

**패턴 코드** — 다중 기준 정렬 · 정렬한 뒤 이웃끼리만 보기 · 좌표 압축

| 역할 | 문제 | 배우는 것 |
| --- | --- | --- |
| 워밍업 | **다중 기준 정렬** ✅ | 비교자와 키 함수 작성 |
| 핵심 | **K번째 큰 수** ✅ | 정렬 후 인덱스로 답 얻기 |
| 핵심 | **좌표 압축** ✅ | 정렬로 값을 순위로 바꿔 범위를 줄이기 |
| 도전 | **애너그램 묶기** ✅ | 정렬 결과를 해시 키로 쓰기 |

### 8주차 — 투 포인터와 슬라이딩 윈도우

이중 반복문을 한 번의 순회로 접는 기술이에요.

**개념** — 형태 1 — 양끝 투 포인터 · 형태 2 — 슬라이딩 윈도우 · 카데인 알고리즘

**패턴 코드** — 양끝 투 포인터 (정렬된 배열) · 가변 길이 슬라이딩 윈도우 · 카데인 알고리즘

| 역할 | 문제 | 배우는 것 |
| --- | --- | --- |
| 워밍업 | **정렬된 배열의 두 수의 합** ✅ | 양끝 포인터의 기본형 |
| 핵심 | **정렬된 배열 중복 제거** ✅ | 읽기 포인터와 쓰기 포인터를 분리하기 |
| 핵심 | **가장 큰 연속 부분 수열의 합** ✅ | 카데인 알고리즘 |
| 도전 | **중복 없는 가장 긴 부분 문자열** ✅ | 가변 윈도우와 해시의 조합 |

### 9주차 — 그리디

당장 최선인 선택이 전체 최선이 되는 경우 — 그리고 안 되는 경우.

**개념** — 그리디가 통하려면 · 자주 나오는 형태 · 그리디가 깨지는 순간

**패턴 코드** — 정렬 후 하나씩 집기 (회의실 배정) · 정렬 후 양끝에서 짝짓기 (구명보트)

| 역할 | 문제 | 배우는 것 |
| --- | --- | --- |
| 워밍업 | **거스름돈 최소 동전 (배수 화폐)** ✅ | 그리디가 성립하는 조건 확인하기 |
| 핵심 | **회의실 배정** ✅ | 끝나는 시각 기준 정렬과 그 이유 |
| 핵심 | **구명보트** ✅ | 정렬 + 투 포인터 그리디 |
| 도전 | **거스름돈** ✅ | 그리디가 실패하는 경험 — 19주차 DP의 동기 |

### 10주차 — 스택 · 큐 · 덱

무엇을 먼저 꺼낼 것인가로 갈리는 세 자료구조.

**개념** — 스택이 답인 신호 · 단조 스택

**패턴 코드** — 괄호 짝 맞추기 · 인덱스 포인터로 만든 큐 · 단조 스택으로 다음 큰 원소 찾기

| 역할 | 문제 | 배우는 것 |
| --- | --- | --- |
| 워밍업 | **올바른 괄호** ✅ | 스택의 교과서적 사용 |
| 핵심 | **최근 K개의 이동 평균** ✅ | 큐와 덱으로 창을 관리하기 |
| 핵심 | **후위 표기식 계산** ✅ | 스택으로 수식 처리하기 |
| 도전 | **다음 큰 원소** ✅ | 단조 스택으로 O(n²)를 O(n)으로 |

### 11주차 — 이분 탐색과 결정 알고리즘

매번 절반을 버려요. 그리고 '답' 자체를 탐색하는 법까지.

**개념** — lower bound와 upper bound · 답을 이분 탐색하기 (파라메트릭 서치)

**패턴 코드** — 기본 이분 탐색 · 답을 이분 탐색하기

| 역할 | 문제 | 배우는 것 |
| --- | --- | --- |

| 핵심 | **삽입 위치 찾기** ✅ | lower bound 변형 |
| 핵심 | **회전된 정렬 배열에서 검색** ✅ | 정렬이 한 번 끊긴 배열에서의 이분 탐색 |
| 도전 | **랜선 자르기** ✅ | 답을 이분 탐색하는 사고 전환 |

## 페이즈 3 · 자료구조와 그래프 (13~18주)

재귀로 구조를 다루기 시작합니다. 트리와 그래프, 그리고 우선순위 큐까지.

### 13주차 — 재귀와 분할 정복

문제를 자기 자신의 작은 버전으로 쪼개는 사고법.

**개념** — 분할 정복 · 재귀와 반복

**패턴 코드** — 메모이제이션으로 중복 계산 없애기 · 병합 정렬 · 빠른 거듭제곱

| 역할 | 문제 | 배우는 것 |
| --- | --- | --- |
| 워밍업 | **재귀 피보나치와 메모이제이션** ✅ | 중복 계산을 직접 체감하기 |
| 핵심 | **거듭제곱 빠르게** ✅ | 분할 정복으로 O(log n) 만들기 |
| 핵심 | **병합 정렬 직접 구현** ✅ | 분할 → 정복 → 병합의 전체 구조 |

## 정해진 규약

### 트리 입출력

테스트 케이스는 JSON이어야 합니다 — 같은 케이스가 두 채점기를 함께 돌아야 하고,
Python 쪽은 `json.loads`로 받기 때문입니다. 트리에는 JSON 표현이 없으므로 **레벨 순서
배열로 쓰고, 채점기가 호출 직전에 노드로 되살립니다.**

```
[3, 9, 20, null, null, 15, 7]        3
                                    / \
null 은 자식 없음                    9  20
뒤쪽 null 은 생략                      / \
                                    15  7
```

문제에 `argShapes: ["tree"]`를 적으면 그 자리의 인자가 노드로 바뀌어 들어가고,
`returnShape: "tree"`를 적으면 반환한 노드가 다시 같은 배열로 직렬화되어 채점됩니다.
스타터에 변환 헬퍼를 붙이는 방식도 검토했지만, 트리 문제가 14주차 이후로도 계속 나오는데
매번 같은 코드가 붙고 사용자가 지우면 깨지므로 채점기 쪽에 한 번만 두었습니다.

`TreeNode`는 두 언어 모두 전역으로 제공되므로 새 노드를 직접 만들 수 있습니다.
제출 코드가 자기 `TreeNode`를 다시 선언해도 채점기 것과 충돌하지 않습니다.

Python에는 함정이 하나 있습니다. `None`은 "빈 트리"와 "아무것도 반환하지 않음"을
구분하지 못합니다. `returnShape`이 선언된 문제에서는 값 쪽으로 해석하므로, 미완성
스텁은 "반환 없음"이 아니라 오답으로 표시됩니다.

### 힙

**한 번 직접 만들고, 그다음부터는 받습니다.** Python은 `heapq`가 내장이라 세 줄이면
끝나지만 JavaScript에는 내장 힙이 없어, 그대로 두면 힙이 필요한 문제마다 같은 40줄을
다시 타이핑하게 됩니다. 두 번째부터는 배우는 것이 없습니다.

- 18주차 1번 `최소 힙 직접 구현` — 스타터는 빈 스켈레톤. 여기서 손으로 만듭니다.
- 그 이후 문제 — `src/lib/problems/snippets.ts`의 `MIN_HEAP_JS`가 스타터로 딸려옵니다.

공유본은 비교자를 받습니다. 21주차 다익스트라처럼 `[거리, 노드]` 짝을 담을 때 JavaScript는
배열을 문자열로 바꿔 비교해서 `[10, x]`를 `[9, x]`보다 앞에 놓기 때문입니다.
`MIN_HEAP_JS`는 `최소 힙 직접 구현`의 모범 답안이기도 해서 `npm run verify`가 매번 실행합니다.

### 프로그래머스 추천 문제

주차마다 [프로그래머스](https://school.programmers.co.kr/learn/challenges)의 추천 문제
67개를 주제별로 붙여 둡니다. **목록만 담습니다** — 번호, 제목, Lv.1~Lv.5 난이도.
지문과 채점 데이터는 프로그래머스 것이라 링크로 연결하고, 푼 것은 체크박스로
표시합니다.

프로그래머스는 백준처럼 공개 인덱스를 내려받을 곳이 없어, 목록은
`src/lib/programmers/recommended.json`에 손으로 관리합니다. **코딩테스트 고득점
Kit**(해시 · 스택/큐 · 힙 · 정렬 · 완전탐색 · 탐욕법 · DP · DFS/BFS · 이분탐색 ·
그래프)을 뼈대로 삼고, 초심자용 Lv.1 문제와 유명 카카오 기출을 주제별로 얹었습니다.

한 주제가 여러 주차에 걸치면 **먼저 배우는 주차**에 둡니다. 앞 주차의 도구로 풀리는
문제라는 뜻이고, 설계 원칙 3번과 같은 규칙입니다.

프로그래머스에 마땅한 문제가 없는 주차(2주차 누적합, 23주차 트라이)와
체크포인트 주차(6·12·24)는 목록을 붙이지 않습니다.

## 사이트에 반영된 것

이 문서는 계획이고, 실제 콘텐츠는 코드에 있습니다.

- `src/lib/curriculum/weeks/w01.ts` ~ `w24.ts` — 24주 개념 노트, 패턴 코드, 셀프 체크
- `/curriculum` — 4페이즈 지도와 전체 진행률
- `/week/[n]` — 개념 → 패턴 → 문제 → 프로그래머스 추천 문제 → 셀프 체크
- 문제 화면에는 소속 주차로 돌아가는 링크가 붙습니다

주차가 가리키는 문제 slug가 실제로 존재하는지, 모든 문제가 정확히 한 주차에
배치됐는지는 `npm run verify` 가 검사합니다.
